# Tandem — ТЗ MVP (пилот)

Nov 23, 2026 · @Ихсан

## 1. О документе

Это рабочее ТЗ на MVP Tandem для пилота: что строим за первую неделю и куда развиваемся дальше. Документ задаёт вектор, а не закон: решения меняются по ходу разработки и по отзывам пилота.

- **Источник истины.** Этот документ заменяет семь PDF проектирования (17–23.11.2026) в части рамок MVP. Детальные правила из PDF можно брать как справку, если они не противоречат этому ТЗ.
- **Пилотные упрощения.** Правило с пометкой «пилот» — временное упрощение ради скорости, а не окончательное продуктовое решение. Его пересматривают после пилота.
- **Как менять.** Новое решение записывается прямо в нужный раздел. Если решение отменяет старое, старое удаляется, а не остаётся рядом.
- **Новый вопрос** рассматривается, только если он блокирует пилот. Остальное идёт в раздел «Вектор развития».

## 2. Продукт

Tandem — социальная платформа для работы: реальные профили людей и компаний плюс рабочее пространство компании, где структура, люди, задачи и переписка собраны в одном месте.

**Два слоя продукта:**

- **Социальный слой** (бесплатно для людей): личные профили, профили компаний, связь человека с местом работы, каталог и поиск. Новостной ленты нет.
- **Рабочий слой** (платно для компании, подписка Team): Canvas со структурой компании, сотрудники, роли, рабочие страницы «Задачи» и «Чат».

**Главное отличие — Canvas.** Структура компании одновременно служит навигацией и картой доступа: рабочая страница привязана к филиалу или отделу, и видно, кто что видит.

**Позиционирование против альтернатив:** Tandem — платформа, а не набор инструментов (в отличие от Битрикс24). Он проще и заменяет рабочие WhatsApp-группы по филиалам. Это гипотеза, её проверяет пилот.

**Первая аудитория:** малый и средний бизнес Казахстана с несколькими точками или филиалами. Язык MVP — русский, валюта — тенге.

## 3. Пилот

Первый пилот — сеть магазинов мужской одежды: 3 филиала, около 100 сотрудников по Казахстану. Затем команды со стартап-аллей и знакомые предприниматели.

**Запуск волнами:**

1. Волна 1: владелец, управляющие и один филиал, примерно 10–20 человек.
2. Волна 2: остальные филиалы, после исправления ошибок первой волны.

**Что проверяем:**

- Рабочие поручения и переписка реально переезжают из WhatsApp в Tandem.
- Canvas понятен сотрудникам и помогает управляющим видеть филиалы.
- Сотрудники заполняют профили и заходят в каталог.
- Владелец готов платить после пилота.

**Критерии успеха** (предложение, согласовать с владельцем до старта):

| Метрика | Цель через 4 недели |
| --- | --- |
| Приглашённые сотрудники, активные еженедельно | ≥ 60% |
| Задачи, созданные за неделю | растут неделя к неделе |
| Рабочая переписка филиала | хотя бы одна WhatsApp-группа заменена чатом Tandem |
| Решение владельца | готов продлить за деньги |

Метрики собираем в PostHog с первого дня пилота.

## 4. Рамки MVP

MVP — это профили и каталог, компания с Canvas и два рабочих модуля: «Задачи» и «Чат». Всё остальное — после пилота.

| Блок | В MVP | После MVP |
| --- | --- | --- |
| Профиль человека | имя, @username, аватар, bio, город, место работы с должностью | навыки, образование, контакты с отдельной видимостью, обложка |
| Профиль компании | логотип, название, описание, основатели, город, число и список сотрудников | адреса, публичная структура, настройки видимости полей |
| Каталог и поиск | две вкладки, поиск по имени во время ввода, фильтр по городу | фильтр по навыкам, ранжирование |
| Вступление в компанию | ссылка-приглашение | заявка с профиля компании, персональные приглашения |
| Роли | 4 фиксированные: Owner, Admin, Manager, Employee | кастомные роли, персональные разрешения, точечные запреты |
| Canvas | дерево, карточки страниц, линии Scope, замки, боковая панель, «+» | личные позиции, мини-карта, поиск по холсту, перетаскивание людей |
| Задачи | Kanban, список, карточка, комментарии | подзадачи, автоархив, слияние правок, вложения |
| Чат | текст, Realtime, непрочитанное, ответы | реакции, закреп, правка, поиск, @упоминания, файлы |
| Уведомления | счётчики непрочитанного; email о назначении задачи (желательно) | колокольчик, push, Telegram-бот |
| Подписка | Team, активация вручную | онлайн-оплата, автопродление, доп. места онлайн |

**Пилотные упрощения:**

- Один человек состоит только в одной компании. Переключателя компаний нет.
- Передача владения, удаление компании и аккаунта — вручную, через поддержку.
- Архив страниц и задач без автоматического удаления по таймеру.
- Квот на число рабочих страниц нет, «Магазина» нет.

**Не делаем в MVP:** новостную ленту, личные сообщения, файлы и вложения, звонки, PWA и нативные приложения, тёмную тему, казахский и английский языки, тарифы Business и Company.

## 5. Сущности и модель данных

Основа модели: Organization → Module → Page → Scope → Content. Каждая рабочая запись несёт `organization_id`. Названия таблиц — рабочие, их можно менять.

| Таблица | Что хранит | Важные правила |
| --- | --- | --- |
| `profiles` | личный профиль, связан с Supabase Auth | `username` уникален; читается всеми авторизованными |
| `organizations` | компания и её публичный профиль | `slug` уникален; одинаковые названия разрешены |
| `memberships` | членство человека в компании: роль, должность, статус | пилот: уникален `user_id` (снять ограничение = разрешить несколько компаний) |
| `units` | подразделение: название, родитель, адрес, руководитель | один родитель, без циклов, имена уникальны внутри родителя |
| `unit_members` | человек в подразделении | можно в нескольких; членство не наследуется |
| `pages` | рабочая страница: модуль (`tasks` / `chat`), название, иконка, статус | активна / в архиве |
| `page_scopes` | кому доступна страница: вся компания, подразделение или человек | доступ по подразделению наследуется вниз |
| `page_access` | вычисленный доступ (человек, страница) | пересчитывается при изменении структуры, Scope и членства; именно её проверяет RLS |
| `tasks` | задача: название, описание, статус, приоритет, ответственный, дедлайн, `version` | `organization_id` совпадает со страницей; `parent_task_id` заложить, но не использовать |
| `task_comments` | комментарии к задаче | мягкое удаление |
| `messages` | сообщения чата, ссылка на ответ | `client_id` уникален (повторная отправка без дублей) |
| `chat_reads` | последнее прочитанное сообщение по паре человек–чат | из неё считается непрочитанное |
| `invites` | ссылка-приглашение: токен, срок, статус | многоразовая, 3 дня |
| `subscriptions` | подписка компании: статус, оплачено до, число мест | один флаг «активна» для всех проверок записи |
| `audit_log` | административные события: кто, что, когда, было / стало | только добавление; интерфейс после MVP |
| `canvas_prefs` | личное состояние Canvas (свёрнутые списки людей) | не влияет на других |

Структура, членство и Scope страницы сводятся в одну таблицу доступа, и RLS проверяет только её.

## 6. Роли и права

В MVP четыре фиксированные роли с заранее заданными правами. Нет кастомных ролей, персональных разрешений и точечных запретов. Должность и назначение руководителем подразделения прав не дают.

| Действие | Owner | Admin | Manager | Employee |
| --- | --- | --- | --- | --- |
| Редактировать профиль компании | да | да | нет | нет |
| Приглашать и удалять сотрудников | да | да | нет | нет |
| Назначать роли Manager и Employee | да | да | нет | нет |
| Назначать и снимать Admin | да | нет | нет | нет |
| Менять должность сотрудника | да | да | нет | нет |
| Создавать, менять, удалять подразделения; распределять людей | да | да | нет | нет |
| Создавать рабочие страницы | да | да | да, доступ только своим подразделениям | нет |
| Менять Scope, архивировать страницу | да | да | только созданные им | нет |
| Работать в доступной странице: задачи, комментарии, сообщения | да | да | да | да |
| Редактировать и архивировать чужую задачу | да | да | в своих страницах | нет |
| Удалять чужие сообщения | да | да | в своих страницах | нет |
| Видеть Canvas и список сотрудников | да | да | да | да |
| Управлять подпиской | да | нет | нет | нет |

**Правила проверки:**

- Каждое действие проверяется на сервере и в RLS по порядку: членство → доступ к странице → роль. Скрытая кнопка защитой не считается.
- По умолчанию всё запрещено. Закрытую страницу нельзя открыть ни по URL, ни через API, ни через Realtime.
- Owner в компании один. Создатель становится Owner автоматически. Owner не может выйти из своей компании.
- В пилоте права Admin и Owner распространяются на всю компанию, без ограничения по подразделениям.

## 7. Аккаунт и личный профиль

Аккаунт бесплатен. Профиль виден всем авторизованным пользователям Tandem.

**Регистрация и вход:**

- Email + пароль или одноразовая ссылка через Supabase Auth; письма через Resend.
- Подтверждение email и восстановление пароля.
- При регистрации по приглашению человек возвращается на это приглашение.
- Без входа сайт недоступен: любая страница ведёт на экран входа. Исключение — предпросмотр приглашения по ссылке (раздел 9).
- После регистрации (первый вход по ссылке из письма) открывается «Главная», при следующих входах — раздел «Работа».

**Профиль:**

- Имя и фамилия (обязательно), @username (создаётся автоматически, можно изменить), аватар, короткое «О себе», город.
- Карточка текущего места работы: логотип, название компании, должность; ведёт в профиль компании.
- Профиль открывается по ссылке `/@username`.
- Редактирование — на отдельной странице.
- Аватар: JPG, PNG или WebP, до 2 МБ, сжатие при загрузке.

**Открытый вопрос для пилота:** место работы в профиле публично. Сотрудники должны знать об этом при вступлении; стоит проверить требования к персональным данным.

## 8. Каталог и поиск

Каталог — ядро социального слоя. В MVP это раздел «Поиск» с двумя вкладками: «Компании» и «Люди».

- До ввода запроса показывается каталог активной вкладки: сначала недавно зарегистрированные.
- Поиск по имени, @username или названию компании, без учёта регистра. Результаты обновляются во время ввода (задержка около 300 мс).
- Запрос сохраняется при переключении вкладки.
- Фильтр по городу — для обеих вкладок.
- Фильтр по числу сотрудников — для компаний: до 10, 11–50, 51–200, более 200. Фильтры открываются кнопкой рядом с поиском.
- На компьютере каталог остаётся в левой колонке, а выбранный профиль открывается справа. Без выбора справа фото команды и заголовок «Расширяйте круг связей». На телефоне профиль открывается отдельной страницей.
- Вкладки «Компании / Люди» — строкой с подчёркиванием выбранной; строка поиска округлая. Компактные вертикальные списки: у человека аватар, имя и место работы без @username; у компании логотип, название, город и число сотрудников.
- Постраничная подгрузка по 20 записей.
- В каталоге только компании с активной или ранее оплаченной подпиской (компания создаётся только после оплаты).

**Технически:** поиск через индекс `pg_trgm` в Postgres. Отдельный поисковый сервис для MVP не нужен.

## 9. Компания, приглашения, сотрудники

Компанию создаёт пользователь с активной подпиской Team, не состоящий в другой компании (пилот). Дальше он приглашает людей по ссылке.

**Создание компании:**

1. Подписка Team активирована для этого пользователя (в пилоте — вручную, см. раздел 14).
2. Форма: название (обязательно), логотип, описание, город.
3. Создатель становится Owner и основателем в профиле компании (основателя можно изменить).
4. Новая компания пустая: ни подразделений, ни страниц. Owner видит панель быстрого старта: «Создать структуру», «Пригласить людей», «Создать страницу».

**Приглашение по ссылке:**

- Многоразовая ссылка, действует 3 дня, её можно отозвать и создать новую.
- По ссылке открывается предпросмотр: логотип, название, кнопка «Присоединиться». Без аккаунта — сначала регистрация, затем возврат к приглашению.
- Сервер при вступлении атомарно проверяет: ссылка действует, подписка активна, есть свободное место, человек не состоит в другой компании.
- У нового сотрудника роль Employee, он попадает в группу «Нераспределённые».

**Раздел «Моя компания»:**

- **Профиль** — тот же публичный профиль компании; Owner и Admin редактируют его прямо на странице.
- **Структура** — Canvas (раздел 10).
- **Сотрудники** — список с поиском; блок «Нераспределённые»; ссылка-приглашение, смена роли и должности, удаление — для тех, у кого есть права.

**Выход и удаление сотрудника:**

- Красная кнопка «Выйти из компании» внизу меню, с подтверждением. Owner выйти не может.
- Доступ к данным компании прекращается сразу, включая Realtime.
- Незавершённые задачи остаются без ответственного; сообщения и история сохраняются с именем автора.
- Руководство подразделениями снимается автоматически.

## 10. Canvas

Canvas — главное отличие Tandem и обязательная часть MVP. Это холст с деревом компании, где видно подразделения, людей и рабочие страницы с их областью доступа.

**Дерево:**

- Корневая карточка — компания. Все вложенные узлы — одинаковые «подразделения», без типов («филиал», «отдел» — просто название).
- У подразделения один родитель, глубина любая, циклов нет.
- Карточка подразделения: название, руководитель (аватар и имя), число прямых сотрудников и уникальных сотрудников всей ветки, список людей (свёрнут по умолчанию).
- «Нераспределённые» — системная группа у корня, а не подразделение.
- Canvas видят все сотрудники компании; изменяют только Owner и Admin.

**Рабочие страницы на холсте:**

- Каждая активная страница — одна карточка с иконкой модуля.
- Scope «вся компания» — линия к корню; Scope подразделений — линии к ним; отдельные люди — счётчик «+N сотрудников» без линий.
- Недоступная страница — серая, с замком, не открывается. На ней видны только название и тип модуля.

**Взаимодействия (MVP):**

- Перемещение и масштаб: мышь и колесо на десктопе, жесты двумя пальцами на телефоне. Ограничения min/max zoom.
- Автоматическая раскладка дерева (например, библиотека `dagre` или `elkjs`); при первом открытии корень по центру.
- Клик по подразделению — боковая панель (на телефоне — на весь экран): руководитель, люди, адрес, страницы, действия по правам (переименовать, назначить руководителя, добавить или убрать людей, удалить).
- Клик по доступной странице сразу открывает модуль.
- «+» у корня и у подразделения: «Создать подразделение» или «Создать страницу» (Scope подставляется по узлу).
- Удалить подразделение с дочерними нельзя, пока детей не перенесли.

**После MVP:** личные позиции карточек, «Привести в порядок», мини-карта, поиск по холсту, перетаскивание сотрудника с выбором «Добавить / Перевести», прямые ссылки на подразделения.

Рекомендуемая библиотека для холста: React Flow (`@xyflow/react`) — перемещение, масштаб, узлы и линии там уже есть.

## 11. Рабочие страницы и Scope

Рабочая страница — один экземпляр модуля («Задачи» или «Чат») со своими данными и областью доступа. Например: «Задачи филиала Астана», «Общий чат».

**Создание:**

1. Откуда: «+» у заголовка «Рабочие страницы» или «+» на Canvas. Кнопка видна только тем, у кого есть право.
2. Выбрать модуль: «Задачи» или «Чат».
3. Название (подставляется по модулю, можно изменить), описание по желанию.
4. Scope обязателен: вся компания, выбранные подразделения и/или выбранные люди.
5. После создания — возврат к списку, новая страница помечена «Новая» до первого открытия.

**Правила доступа:**

- Страница подразделения доступна его сотрудникам и сотрудникам всех дочерних подразделений. Вверх доступ не наследуется.
- Owner и Admin видят все страницы компании.
- Перевод человека между подразделениями пересчитывает доступ автоматически, без предварительного экрана.
- Изменение Scope самой страницы применяется ко всему её содержимому и требует подтверждения.

**Список «Рабочие страницы»:** только доступные, новые сверху, поиск по названию, фильтр по модулю. На телефоне — компактный вертикальный список.

**Архив:** архивная страница исчезает с Canvas и из списка. Её можно читать во вкладке «Архив» и восстановить. Автоматического удаления через 7 дней в пилоте нет. Клонирование и смена типа модуля не предусмотрены.

## 12. Модуль «Задачи»

Задача всегда принадлежит одной рабочей странице и видна всем, у кого есть доступ к этой странице. Переносить задачу на другую страницу нельзя.

| Поле | Правило |
| --- | --- |
| Название | обязательно, не из одних пробелов |
| Описание | обязательно |
| Ответственный | необязателен; только человек с доступом к странице; при создании автор не может выбрать себя (см. открытые вопросы) |
| Соисполнители | необязательны |
| Дедлайн | обязателен, дата и время в будущем |
| Приоритет | низкий, обычный (по умолчанию), высокий, срочный |
| Статус | «Нужно сделать», «В работе», «Готово»; переходы свободные |
| Просрочка | вычисляемая отметка «Просрочено», не статус |

**Представления:**

- **Kanban**: три колонки по статусам, перетаскивание сразу сохраняет статус (при ошибке карточка возвращается). По 20 карточек в колонке, дальше «Показать ещё».
- **Список**: таблица со столбцами статус, ответственный, дедлайн, приоритет.
- Карточка на доске: название, ответственный, дедлайн, приоритет, «создано N назад». Свои задачи выделены фоном.
- Фильтры общие для обоих видов: «Мои задачи», ответственный, приоритет, просроченные; в списке ещё статус. Поиск по названию.

**Карточка задачи** (боковая панель на десктопе, на весь экран на телефоне):

- Открывается для просмотра; редактирование — отдельным режимом с кнопкой «Сохранить» и предупреждением о несохранённых изменениях.
- Комментарии: пишут автор, ответственный, соисполнители, Manager, Admin и Owner. Свой комментарий можно изменить и удалить. Ссылки — обычным текстом, файлов нет.
- Короткая история действий: создание, смена статуса, ответственного и дедлайна.
- Прямая ссылка на задачу открывает её карточку (при наличии доступа).

**Кто что меняет:**

- Статус — ответственный, соисполнители, автор, Manager, Admin, Owner.
- Поля и назначения — автор, Manager, Admin, Owner.
- Архивация задачи — автор, Manager, Admin, Owner. Архив — третья вкладка рядом с «Доска» и «Список».

**Одновременное редактирование:** сервер проверяет `version`. Если задачу уже изменили, показываем «Задача изменена, обновите», а введённый текст остаётся в форме. Автоматического слияния правок в MVP нет.

**После MVP:** подзадачи и прогресс, автоархив готовых через 30 дней, напоминания о дедлайнах, отчёт при завершении, вложения.

## 13. Модуль «Чат» и раздел «Сообщения»

Корпоративный чат — это рабочая страница типа «Чат». Участники чата — все, кому доступна страница по Scope. Личных сообщений в MVP нет.

**В MVP:**

- Текстовые сообщения в реальном времени: автор, аватар, время. История хранится в Postgres.
- Enter отправляет, Shift+Enter — новая строка. Пустое не отправляется. Лимит 4 000 символов.
- При ошибке сети — отметка «Не отправлено» и повтор без дублей (`client_id` создаётся на клиенте).
- Ответ на сообщение: цитата с переходом к оригиналу, без тредов.
- Автор удаляет своё сообщение; вместо него видно «Сообщение удалено».
- Счётчик непрочитанного по паре человек–чат. В MVP чат считается прочитанным до последнего сообщения при открытии и прокрутке вниз; точное прочтение по видимости — позже.
- История подгружается по 50 сообщений при прокрутке вверх.
- При потере доступа чтение, отправка и Realtime-события прекращаются сразу.
- Архивный чат можно читать, писать нельзя.

**Раздел «Сообщения»:** один список доступных чатов компании, как в WhatsApp: сортировка по последнему сообщению, время, счётчик непрочитанного. Это тот же чат, что и в «Работе»: одна история и один счётчик. Создать чат отсюда нельзя. Нет чатов — иллюстрация и «Здесь пока нет сообщений».

**После MVP:** реакции, закреп, редактирование в течение 15 минут, поиск внутри чата, @упоминания, режим «Без звука», личные сообщения, файлы и фото.

## 13А. Модуль «Отметки» (GPS)

Сотрудник отмечает приход и уход с телефона, и только находясь в зоне своего филиала. Входит в MVP до запуска пилота; план недели увеличивается примерно на 1–2 дня.

**Настройка зоны (Owner, Admin):**

- У подразделения появляется точка отметки: координаты и радиус (по умолчанию 50 м).
- Задать точку: кнопка «Я нахожусь в филиале — взять текущие координаты» или точка на карте.
- Отмечаться можно в любом подразделении, где сотрудник состоит напрямую и где задана точка.

**Отметка (сотрудник):**

1. Кнопка «Отметить приход» / «Отметить уход» вверху раздела «Работа».
2. Браузер запрашивает геолокацию; клиент отправляет координаты и точность.
3. Сервер сам считает расстояние до точки и ставит время своими часами. Решение клиента «я в зоне» не принимается.
4. В зоне — отметка сохраняется. Вне зоны или слишком низкая точность — отказ с понятной причиной («вы в 120 м от филиала», «включите геолокацию»), попытка записывается в журнал.
5. Нельзя отметить приход дважды подряд без ухода.

**Просмотр (Owner, Admin, Manager своих подразделений):** таблица за день по филиалу — сотрудник, приход, уход, часы. Сотрудник видит только свои отметки.

**Данные:** таблица `attendance_events` — `organization_id`, `unit_id`, `user_id`, тип (приход / уход), серверное время, координаты, точность, расстояние, результат. У `units` добавляются `lat`, `lng`, `radius_m`.

**Ограничения, о которых нужно знать:**

- В торговых центрах GPS в помещении часто ошибается сильнее 50 м. Радиус и допустимую точность подобрать на месте в каждом филиале пилота.
- Из браузера нельзя надёжно распознать подмену геолокации. Для пилота это приемлемо; позже можно добавить селфи при отметке или нативное приложение.
- Геолокация работает только по HTTPS и после разрешения пользователя. Нужна короткая инструкция «как включить» для iPhone и Android.
- Координаты сотрудника собираются только в момент нажатия кнопки, без фонового отслеживания. Это важно и для доверия, и для персональных данных.

**После MVP:** графики смен и опоздания, табель за месяц с экспортом, ручная корректировка отметки руководителем с записью в журнал, селфи при отметке.

**Как добавлять новые модули.** Модули бывают двух видов:

- **Модули страниц** («Задачи», «Чат», будущая база знаний): у компании много экземпляров, доступ через Scope и `page_access`.
- **Модули компании** («Отметки», будущие графики смен): один на компанию, привязан к подразделениям, включается в настройках.

Общие правила для любого нового модуля: своя папка в коде (`modules/<имя>`), свои таблицы с `organization_id`, права через общие функции доступа, запись в реестре модулей (`modules`) и флаг включения для компании (`organization_modules`). Тогда новый модуль не трогает код существующих.

## 14. Подписка Team

Базовый тариф — Team: 9 000 ₸ в месяц, 15 мест включая Owner. Дополнительные места покупаются по одному; цена места — открытый вопрос.

**Пилотный режим (без интеграции платежей):**

- Оплата проходит вне системы (перевод или счёт) или пилот бесплатный по договорённости.
- Суперадминистратор Tandem (вы) включает подписку в внутренней админке или SQL: статус, дата окончания, число мест.
- После активации пользователь видит кнопку «Создать компанию».

**Правила, которые работают уже в MVP:**

- Все записи в рабочем пространстве проверяют один флаг «подписка активна».
- Приглашение не срабатывает, если все оплаченные места заняты. Owner видит понятное сообщение.
- Подписка истекла — данные доступны только для чтения, новые вступления закрыты. Все видят баннер, Owner — кнопку «Продлить» (в пилоте она ведёт на контакт для оплаты).
- Страница «Подписка» для Owner: тариф, статус, оплачено до, места занято / куплено.

**После пилота:** онлайн-оплата (кандидат — Dodo Payments, варианты с Kaspi и счётом для ТОО нужно проверить), автопродление с согласия, покупка мест онлайн, 24-часовая отсрочка, история платежей, тарифы Business и Company.

## 15. Навигация и экраны

Пять глобальных разделов: нижняя панель на телефоне, боковая на десктопе. Без входа разделы недоступны. После регистрации открывается «Главная», при обычном входе — «Работа».

| Раздел | Что внутри в MVP |
| --- | --- |
| Главная | заглушка с изображением и сообщением о будущей ленте; лента — позже |
| Поиск | каталог «Компании / Люди» |
| Работа | рабочее пространство компании |
| Сообщения | список доступных чатов |
| Профиль | личный профиль, редактирование, настройки аккаунта, выход |

**«Работа», если компании нет:** иллюстрация и текст «Вы пока не состоите ни в одной компании». В шапке иконки «Найти компанию» и «Создать компанию» (вторая активна при активной подписке).

**«Работа», если компания есть:**

- Шапка: логотип и название компании; у Owner — значок «Подписка».
- Меню компании (бургер слева на телефоне): «Рабочие страницы», «Моя компания» (Профиль, Структура, Сотрудники), «Настройки» (для Owner и Admin), внизу красная «Выйти из компании».
- Основная область: список доступных рабочих страниц с «+» для тех, у кого есть право.
- Нет доступных страниц — «У вас пока нет доступных рабочих страниц».

**Список экранов MVP (\~17):** вход, регистрация, восстановление пароля, профиль человека, редактирование профиля, профиль компании, каталог, создание компании, предпросмотр приглашения, «Работа», сотрудники, Canvas, создание страницы, страница задач (доска, список, архив, карточка), страница чата, «Сообщения», подписка и настройки компании.

**Интерфейс:** адаптивный сайт, сначала под телефон (сотрудники магазинов работают с телефона). Светлая тема, русский язык; строки вынесены из кода для будущих казахского и английского.

## 16. Технические требования и безопасность

Стек: Next.js + TypeScript, Supabase (Postgres, Auth, Realtime, Storage), Vercel, GitHub, Resend, Sentry, PostHog. Разработка с помощью Claude Code и Codex.

**Обязательно с первого дня:**

1. **Изоляция компаний.** `organization_id` в каждой рабочей таблице; база не даёт задаче или сообщению ссылаться на страницу другой компании.
2. **Одна точка доступа.** Функция пересчёта `page_access` при изменении структуры, Scope и членства. RLS для задач, комментариев и сообщений проверяет только эту таблицу. По умолчанию запрет.
3. **Тесты RLS.** Набор сценариев с двумя компаниями и несколькими ролями: чужая компания, закрытая страница, вышедший сотрудник. Прогонять перед каждым деплоем.
4. **Серверные операции.** Создание компании, вступление по ссылке, смена роли, изменение Scope — через RPC или Server Actions с проверкой прав, а не прямыми записями с клиента.
5. **Realtime только по доступным страницам.** Проверить на двух аккаунтах, что чужие события не приходят.
6. **Идемпотентность** отправки сообщений и вступления по ссылке.
7. **Два окружения:** отдельные проекты Supabase для тестов и продакшена, миграции в Git.

**Защита и наблюдение:**

- Ограничение частоты: сообщения, создание задач, регистрация.
- Пагинация и индексы на всех списках.
- Аватары и логотипы — лимит размера и формата.
- Sentry — ошибки; PostHog — события пилота (вход, создание задачи, сообщение, открытие Canvas, просмотр профиля).
- Журнал `audit_log` пишется сразу, интерфейс к нему — после MVP.

**Правила работы с ИИ:** каждую RLS-политику и миграцию читать самому и проверять тестом; не давать ИИ `service_role`-ключ в клиентском коде; коммитить маленькими шагами.

Цель недели — первая волна пилота работает в продакшене. Если что-то отстаёт, первым упрощаем задачи и чат, не Canvas и не каталог. Безопасность первого дня не урезаем.

| День | Что делаем | Готово, если |
| --- | --- | --- |
| 1 | Проект, схема БД, Auth, `organization_id`, функция `page_access`, RLS, тесты, деплой каркаса | тест на двух компаниях проходит, сайт открывается на Vercel |
| 2 | Профили людей и компаний, редактирование, каталог с поиском | нахожу человека и компанию по имени с телефона |
| 3 | Ручная активация Team, создание компании, приглашение по ссылке, сотрудники, роли, подразделения | второй аккаунт вступает по ссылке и попадает в «Нераспределённые» |
| 4 | Canvas: холст, раскладка, карточки, боковая панель, «+» | структура пилота (3 филиала) собрана и читается на телефоне |

| 6 | Модуль «Чат», раздел «Сообщения», счётчики непрочитанного | два телефона переписываются в реальном времени |
| 7 | Проверка приёмочных сценариев, исправления, запуск первой волны (10–20 человек) | владелец и управляющие вошли и создали первые задачи |

**Приёмочные сценарии (день 7):**

- [ ] Новый пользователь регистрируется, заполняет профиль и находит компанию в каталоге.
- [ ] Owner создаёт компанию, структуру и первую страницу; Scope работает правильно.
- [ ] Сотрудник вступает по ссылке и видит только разрешённые страницы; на Canvas закрытые с замком.
- [ ] Прямая ссылка на закрытую страницу и запрос к API возвращают отказ.
- [ ] Один чат через «Работу» и «Сообщения» показывает одну историю и один счётчик.
- [ ] Сотрудник выходит из компании и теряет доступ к данным и событиям Realtime.
- [ ] Истёкшая подписка включает режим чтения.
- [ ] Все основные экраны работают на телефоне.

## 19. Открытые вопросы

Разработку эти вопросы не блокируют, но их нужно закрыть до запуска пилота или до коммерческого запуска.

- [ ] **Цена дополнительного места.** 200 ₸ из старой спецификации или другая сумма? Для пилота на 100 человек это определяет счёт.
- [ ] **Условия пилота.** Бесплатно, со скидкой или полная цена; срок; что будет после. Зафиксировать с владельцем заранее.
- [ ] **Запрет назначать себя ответственным.** Оставить или разрешить? Управляющий филиала не сможет записать задачу себе.
- [ ] **Обязательные описание и дедлайн задачи.** Не замедлит ли это быстрые поручения в магазине? Проверить на первой волне.
- [ ] **Email-уведомления о назначении.** Делаем в неделю или на первое время договариваемся, что управляющие дублируют важное?
- [ ] **Публичность места работы.** Предупреждение при вступлении и проверка требований к персональным данным.
- [ ] **Онлайн-оплата.** Провайдер (Dodo Payments, Kaspi, счёт для ТОО) и закрывающие документы — до коммерческого запуска.
- [ ] **Структура пилота.** Какие подразделения внутри филиалов и какие страницы создать на старте (собрать с владельцем до дня 4).

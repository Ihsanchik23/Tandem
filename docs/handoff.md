## 2026-11-24 — сессия «База данных» (Supabase)

Передача от ИИ, который создавал базу в соседней сессии. Это контекст, а не задачи к выполнению.

### Что сделано по базе (Supabase, проект Tandem, Франкфурт, `msgsvyetosqzkkphcbkq`)
- Создано и применено 10 миграций из `supabase/migrations/`:
  - ядро: профили, компании, членство, подразделения, модули, страницы, Scope, `page_access`, подписки, приглашения, журнал;
  - функции доступа, RLS, RPC;
  - задачи, чат, GPS-отметки, поиск;
  - хранилище: бакеты `avatars` и `logos`;
  - Realtime: `messages`, `tasks`, `task_comments`;
  - индексы.
- Имена файлов миграций совпадают с версиями, записанными в Supabase. **Не переименовывать**, иначе история миграций разойдётся.
- Тесты прав: `supabase/tests/rls_test.sql` (62 проверки) и `modules_test.sql` (57).
  - Прогнаны до применения миграций на копии Postgres с имитацией окружения Supabase, без Docker.
  - Все 119 прошли.
- Проект проверен советником безопасности Supabase. Остались только ожидаемые предупреждения:
  - RPC с `security definer` вызываются вошедшими пользователями;
  - `get_invite_preview` вызывается без входа.
  - Каждая функция сама проверяет права.
- Все RPC, коды ошибок и правила описаны в `supabase/README.md` и в скилле `.claude/skills/tandem-supabase/SKILL.md`.

### Решения, заложенные в базу
- **Роли.**
  - Роли фиксированные: `owner`, `admin`, `manager`, `employee`.
  - Admin назначает и снимает только owner.
  - Owner в компании один и не может выйти из неё.
- **Manager.**
  - Создаёт страницы только для своих подразделений и их дочерних.
  - Редактирует задачи на страницах, к которым у него есть доступ.
- **Назначение себя.** При создании задачи автор не может назначить ответственным себя (`self_assign_forbidden`). Так написано в ТЗ, но это открытый вопрос. Если правило отменят, в базе это одна строка.
- **Потеря доступа.** Когда ответственный теряет доступ к странице, база сама снимает назначение.
- **Одна компания.** Пилот: один человек — одна компания, это уникальный индекс `memberships_one_org_per_user`.
- **Подписка.**
  - Компания создаётся только при активной подписке.
  - В пилоте подписку включает суперадмин через RPC `admin_activate_subscription`.
  - При истёкшей подписке база разрешает только чтение.

### Что предложено пользователю, решение пока не принято
- **Ограничение частоты** для сообщений и задач. В базе его нет. Предложено около 30 сообщений в минуту и 60 задач в час на человека.
- **Сделать репозиторий приватным сейчас**, а не после пилота. Секретов в репозитории нет, ключ `service_role` в проекте не нужен. Пользователь в сессии фронтенда сказал, что закроет репозиторий после запуска.
- Остальные открытые вопросы — в `docs/TZ_MVP.md`, раздел 19.

### Что впереди
- День 2: регистрация и вход, затем навигация, профиль, каталог.
- После регистрации пользователя:
  - его аккаунт нужно сделать суперадмином (запись в `public.platform_admins`);
  - включить подписку Team для компании пилота.
- Письма Auth пока идут через встроенную почту Supabase, у неё лимит писем в час. Resend с доменом подключить к пилоту.
- Sentry и PostHog — день 8.

## 2026-11-23/24 — сессия «Каркас и деплой» (задача 1.1)

### Правила работы с пользователем
- Пользователь не программист и сам не пишет код и не вводит команды. Все команды (git, npm, supabase, vercel) выполняет ИИ. Это правило 7 в `CLAUDE.md`.
- Перед кодом показать план: какие файлы и зачем. Код писать только после подтверждения.
- Объяснять простым языком. Если нужна авторизация в сервисе, точно сказать, что нажать.
- Миграции не создавать и не менять, SQL в базе не выполнять. Новые библиотеки ставить только с согласия пользователя.

### Что сделано
1. **Git и GitHub.**
   - Ветка `main`, remote `https://github.com/Ihsanchik23/Tandem.git`.
   - Репозиторий публичный, поэтому секреты не коммитить.
   - `gh` уже авторизован.
2. **Задача 1.1 «Каркас проекта».**
   - **Стек и настройки.**
     - Next.js 16.4.6 (App Router, Turbopack), React 19, TypeScript strict, Tailwind 4, ESLint 9.
     - В `next.config.ts` включены `cacheComponents` и `partialPrefetching`.
     - Next 16 отличается от привычного: сверяться с `node_modules/next/dist/docs/` (см. `AGENTS.md`). Middleware теперь называется `src/proxy.ts`.
   - **Скрипты.**
     - `lint`;
     - `typecheck` = `next typegen && tsc --noEmit`. `typegen` нужен для глобальных `LayoutProps`/`PageProps`;
     - `test` = `node --test "src/**/*.test.ts"`. Это встроенный тестировщик Node 24, без библиотек. Тесты импортируют файлы с расширением `.ts`, поэтому в tsconfig включён `allowImportingTsExtensions`;
     - `gen:types` перегенерирует `src/lib/supabase/database.types.ts`.
   - **Supabase через `@supabase/ssr`.**
     - `src/lib/supabase/client.ts` — браузер;
     - `server.ts` — сервер, через cookies;
     - `proxy.ts` — `updateSession`, вызывается из `src/proxy.ts`;
     - `env.ts` — чтение переменных.
     - Пакет `server-only` не установлен, ставить только с согласия.
   - **Интерфейс.**
     - Строки интерфейса в `src/lib/i18n/ru.ts`, доступ через `t` из `@/lib/i18n`.
     - Тема только светлая, `lang="ru"`, шрифт Geist с кириллицей.
   - **Файлы и окружение.**
     - Пустые папки модулей лежат с `.gitkeep`.
     - `.env.example` с пустыми переменными.
     - `.env.local` (в gitignore) содержит `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` и `VERCEL_OIDC_TOKEN` от Vercel CLI.
     - Выполнены `supabase init` и `supabase link` к `msgsvyetosqzkkphcbkq`. Supabase CLI авторизован.
3. **Деплой на Vercel.**
   - Команда `tandem-01`, проект `tandem`, связан с GitHub. Push в `main` сам запускает продакшен-деплой.
   - Продакшен: https://tandem-brown-alpha.vercel.app
   - Переменные Supabase заданы для production, preview и development.
   - MCP-коннектор Vercel не имеет доступа к команде `tandem-01` (403). Работать через `npx vercel@latest ... --scope tandem-01`, CLI авторизован.
4. **Sentry перенесён на день 8** по решению пользователя, отражено в `docs/tasks.md`.

### Долги и заметки
- **Тесты RLS.** Архитектор базы прогоняет их на локальном Postgres. На 2026-11-24 проходят все 125, включая 6 тестов лимитов. Docker для этого не нужен.
- **Ограничение частоты** сделано миграцией `20261124061253_rate_limits`: 30 сообщений и 30 комментариев в минуту, 60 задач в час, ошибка `rate_limited`.
- **Репозиторий** остаётся публичным до конца пилота, это решено.
- npm в этом окружении очень медленный. Долгие установки запускать в фоне.
